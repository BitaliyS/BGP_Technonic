# Технониколь-ИИ — концепция продукта

Прототип сервиса ИИ-проверки договоров для компании Технониколь с фирменным логотипом.

## Стиль UI/UX

- Оформление в красно-белой фирменной гамме Технониколь.
- Чтобы беречь глаза, допускаются более умеренные тона с переключением темы (светлая / умеренная тёмная).

## Главный экран юриста

Юрист попадает на главный экран. Слева — сайдбар.

### Сайдбар

- Пункт **«Технониколь-ИИ»** — чат с ИИ.
- При открытии рядом с сайдбаром доступна кнопка **«Создать проект»**.
- Юрист может создать **неограниченное количество проектов**.

### Проект и контекст

- В рамках одного проекта держится контекст **независимо от количества чатов** внутри проекта.
- Агент должен понимать, если уже есть разобранные случаи или сделанный документ, и удерживать контекст запроса.
- Для поддержания контекста в проекте предполагается настройка агента **Hermes**.

### Чаты внутри проекта

- Внутри проекта юрист может создавать **сколько угодно новых чатов**.
- Есть окно запроса в стиле **Claude** (Claude-like): можно загрузить документ, дать пользовательский запрос или выбрать функцию **«Проверить»** с выбором:
  - Договор аренды ТС
  - Недвижимость

### Проверка договора

- Юрист загружает документ и при нажатии **«Проверить»** запускается определённый **плейбук проверки**.
- В окошке чата справа открывается загруженный договор.
- После проверки подсвечиваются пункты договора, которые были проверены.
- В чате выводится **список ошибок**.
- В договоре справа выводится **комментарий с привязкой к конкретному пункту**.
- Юрист может сразу вносить правки **в режиме онлайн**.

Часть реализации берётся из проекта **Ur_Agent 2.0** (блок редактора документов) и из блока **НейроЛис**.

### Анонимизация

В сайдбаре / зоне ввода запроса есть функция **«Анонимизация»**:

- при нажатии загруженный документ сразу выводится на экране слева (как задумано в макете потока);
- персональные и коммерческие данные затираются на **Python** (удаляются / маскируются).

### Модели

Можно настроить переключение моделей на разные базовые.

### Версионность Word

Версионность Word-файлов, с которыми работает юрист в ИИ-чате, должна поддерживаться.

## Личный кабинет руководителя

Самое важное: по проверенному договору подсчитывается количество ошибок, которые заносятся в базу **по юристу** и **по конкретному договору**:

- что был за договор;
- количество ошибок;
- можно развернуть описание найденных ошибок.

У руководителя есть дополнительная вкладка **«Моя команда»** — дашборд руководителя (частично можно взять из проекта Migrator CRM).

Дашборд:

- количество юристов в команде;
- статистика найденных ошибок по договорам;
- по типам договоров — самые частые повторяющиеся ошибки;
- аномалии по типу договора (редкие ошибки);
- сколько договоров проверено за день / неделю / месяц;
- фильтры по типам договоров.

Все эти данные собираются с помощью ИИ: он определяет тип договора в начале проверки. По ним можно отслеживать показатели и принимать управленческие решения.

## Рабочее пространство юриста (бывш. «Drive-тест»)

Отдельная навигационная вкладка «Drive» не нужна: тот же сценарий встроен в **Технониколь-ИИ**:

- создаётся проект, загружается документ;
- справа — панель договора (как у пространства Drive / Ur_Agent);
- чат с функциями проверки; онлайн-подсветка пунктов и комментарии для юриста.

## Админский кабинет

Предполагает **песочницу** (как у Migrator), где юрист-администратор может:

- настраивать промпты под конкретный тип договора;
- поддерживать **версионность промптов** (видно, когда изменялся и какой был промпт до этого);
- добавлять и удалять пользователей.

## Агентская инфраструктура

Продукт строится на агентской инфраструктуре для более качественной работы: подключаются нужные скиллы для работы с документами (Hermes и связанные skills).

| Источник | Что брать |
